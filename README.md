# Есть идея — сайт-визитка

Одностраничный сайт коммерческого бренда **«Есть идея»**: позиционирование, три пути (Идея → MVP, Restyle, Бизнес под ключ как следующий этап), процесс, принципы, FAQ и форма запроса на диагностику.

Статический HTML + CSS + минимальный vanilla JS, без фреймворков и сборки. Раздаётся крошечным Node-сервером без зависимостей, который дополнительно генерирует runtime-конфигурацию контактов из переменных окружения.

## Структура

```
.
├── server.js                 # HTTP-сервер: статика, /config.js, /healthz, robots, sitemap
├── package.json              # start: node server.js, Node >= 20
├── railway.json              # NIXPACKS, npm start, healthcheck /healthz
├── .env.example              # описание переменных окружения
├── public/
│   ├── index.html            # главная (одна страница, якоря)
│   ├── privacy.html          # политика обработки данных
│   ├── 404.html
│   ├── styles.css
│   ├── app.js                # меню, анимация мотива, контакты, форма
│   ├── js-detect.js          # ставит класс .js (анимации только при JS)
│   ├── favicon.svg / favicon.png / og.png
│   └── fonts/                # Manrope (SIL OFL 1.1), кириллица + латиница
└── scripts/
    ├── generate-images.js    # og.png и favicon.png через headless Chromium
    ├── og-template.html, favicon-template.html
    └── check-content.js      # проверка на запрещённые формулировки
```

## Локальный запуск

```bash
npm start
# → http://localhost:3000
```

Зависимостей нет, `npm install` не нужен. Чтобы проверить разные режимы контактов, задайте переменные перед запуском:

```bash
# Windows PowerShell
$env:CONTACT_EMAIL="hello@example.com"; npm start

# bash
CONTACT_EMAIL=hello@example.com FORM_ENDPOINT=https://example.com/hook npm start
```

## Переменные окружения

Все переменные необязательны. Сайт корректно работает без них: контакты показываются как «уточняются», форма отключается с понятным объяснением. Значения читаются при старте процесса.

| Переменная | Назначение |
| --- | --- |
| `CONTACT_EMAIL` | Публичный e-mail. Кнопка «Написать на почту»; запасной способ отправки формы через `mailto:`, если нет `FORM_ENDPOINT`. Также адрес для запросов на удаление данных на странице политики. |
| `CONTACT_TELEGRAM_URL` | Ссылка `https://t.me/...` или `tg:`. Кнопка «Написать в Telegram». |
| `FORM_ENDPOINT` | URL, принимающий `POST` с JSON-телом формы (поля: `name`, `company`, `stage`, `stageLabel`, `message`, `contact`, `consent`, `source`, `page`, `submittedAt`). Если задан — форма отправляет данные через `fetch` и показывает статус. Origin endpoint автоматически добавляется в `connect-src` CSP. |
| `SITE_URL` | Публичный адрес без завершающего слэша. Подставляется в `canonical`, Open Graph, `robots.txt` и `sitemap.xml`. Без него canonical и `og:url` не выводятся, ссылки остаются относительными. |
| `PORT` | Порт. Задаётся платформой; локально по умолчанию `3000`. |

Логика формы на клиенте:

1. есть `FORM_ENDPOINT` → `fetch` POST JSON, состояния «Отправляем…» / успех / ошибка;
2. нет endpoint, но есть `CONTACT_EMAIL` → форма собирает письмо и открывает `mailto:`;
3. ничего не задано → форма отключена, показан текст «Контакты уточняются», пустые кнопки не рендерятся.

## Endpoints сервера

| Путь | Что отдаёт |
| --- | --- |
| `/` | главная страница |
| `/privacy.html` | политика обработки данных |
| `/config.js` | `window.SITE_CONFIG = {...}` из переменных окружения (`no-store`) |
| `/healthz` | `200 ok` |
| `/robots.txt`, `/sitemap.xml` | генерируются с учётом `SITE_URL` |
| остальное | статика из `public/` с MIME-типами и кэш-заголовками; шрифты и изображения — `immutable`, HTML — `no-cache` |

## Деплой на Railway

Репозиторий деплоится как есть:

- builder: NIXPACKS (см. `railway.json`), Node ≥ 20 определяется по `package.json`;
- start command: `npm start`;
- порт: берётся из `PORT`, который Railway выставляет автоматически;
- healthcheck: `GET /healthz`;
- переменные: задать в Variables сервиса `CONTACT_EMAIL`, `CONTACT_TELEGRAM_URL`, `FORM_ENDPOINT`, `SITE_URL` (все опциональны). После смены переменных сервис перезапускается — пересборка не нужна.

## Регенерация изображений

`og.png` (1200×630) и `favicon.png` (512×512) закоммичены. Если меняется шаблон:

```bash
npm run og
# использует локальный Chrome/Edge/Chromium в headless-режиме; путь можно указать в BROWSER_PATH
```

## Правила контента

Сайт — публичная витрина бренда, поэтому к тексту применяются жёсткие ограничения. Автоматическая проверка: `npm run check` (код выхода 1 при нарушениях).

- Название бренда пишется только кириллицей, в два слова с пробелом: **Есть идея**. Любые латинские транслитерации, переводы и слитные написания недопустимы — в тексте, метатегах, alt, комментариях и документации.
- Обещание бренда: «Есть идея — превращаем идеи в работающие продукты и бизнесы.» Главный CTA: «Есть идея? Покажите её.»
- Три услуги с точными названиями: «Новый проект — Идея → MVP», «Старый проект — Restyle», «Бизнес под ключ». Первые две — текущие предложения. Третья подаётся честно как следующий этап: координируемый маршрут с партнёрами, а не готовый пакет; состав, ответственность и юридические границы зависят от юрисдикции и проекта.
- Запрещены: цены и вилки цен; кейсы, имена клиентов, отзывы, логотипы, метрики и цифры «до/после»; превосходные степени и слова-обещания из avoid-листа бренд-системы; названия внутренних проектов и операционного контура; утверждения о зарегистрированном юридическом лице и реквизиты; выдуманные размеры команды, годы опыта, количество клиентов; технологический хайп. AI упоминается один раз — как часть рабочего метода, не как заголовок.
- Контакты не хардкодятся: только через переменные окружения. Домен не придумывается.
- Язык — русский, типографика: кавычки-«ёлочки», тире «—», неразрывные пробелы в заголовках.
